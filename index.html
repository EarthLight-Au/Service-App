How this was set up (reference only)

Already done for the whole team — nothing to redo. Kept here for whoever maintains this in future (e.g. if the Azure app ever needs recreating).

1
Register an app in Azure Portal
portal.azure.com → Microsoft Entra ID → App registrations → New registration. Redirect URI set to Single-page application (SPA), pointed at this app's GitHub Pages URL.
2
Application (client) ID + Directory (tenant) ID
Both copied from the app's Overview page and baked into the build below — that's why nobody needs to paste them in themselves. The tenant ID matters because this app is registered single-tenant ("My organization only"), so sign-in has to point at this specific tenant rather than the generic multi-tenant endpoint.
3
API permissions
Microsoft Graph → Delegated → Files.ReadWrite and User.Read. Neither needed admin consent in this tenant.
4
Shared company folder
Shared with each technician's account with Edit access, and its link baked into the build the same way as the Client ID.
5
All that's left, ever, per person
Sign in below. Every visit submitted after that auto-uploads as PDF + JSON into the shared folder, one pair of files per visit, covering every tower on it — under your own name for traceability, in one place for the team.

Send-to Settings

The Email button sends via your own Microsoft sign-in (the same one used for OneDrive) — so it comes from whichever tech is signed in, no separate email setup needed. If the visit has a site contact email filled in, you'll get a one-tap prompt asking whether to send them a copy too.

What works offline

Once this page has loaded once, everything works with no signal at all: filling in a visit, adding towers, adding parts from the price book, saving, totals, GPS entry, PDF generation. Everything is held in this browser's local storage, and the app itself is cached on the device (via its service worker) so it opens with zero bars of signal — not just while the tab happens to still be open. Nothing leaves the device until you trigger it (Email, or an automatic OneDrive sync once you're back in range).

Installing it like an app

On mobile (iOS/Android), open this page in Safari or Chrome and use Add to Home Screen — it installs properly (icon, splash screen, no browser address bar) because the page ships a manifest + offline service worker. On desktop, use the install icon in Chrome's address bar. Install it once while you still have signal; after that it's yours to use anywhere.

Multiple towers on one report

A "Visit" is one site call-out and can hold several towers. Use + Add tower under the visit details to add another — each tower gets its own Tower Details, Condition, Findings, Parts & Cost and Photos, switchable via the tower tabs. Tap Report to generate one combined PDF covering every tower on the visit, each on its own page, with a visit summary and grand total up front.

PDF report

Tap Report at the bottom to preview, then Download PDF to save a properly formatted EarthLight Site Service Report — with every tower on the visit — to your device. This is the full file (with photos) that gets uploaded to OneDrive.

Emailing the report

The Email button sends the report itself, from inside the app, with the PDF attached — no mail app hand-off, and no separate setup. It uses the same Microsoft sign-in as OneDrive, so it sends from whichever tech is signed in at the time (their own EarthLight mailbox), always to the office inbox configured under Send-to Settings. If the visit has a site contact email filled in, you'll get a one-tap prompt asking whether to also send them a copy — say no and it's office-only. If you're not signed in yet, the Email button will prompt you to sign in first.

OneDrive auto-upload

OneDrive is already configured for the whole team — just sign in once with your own Microsoft work account under the OneDrive tab, and every subsequent visit submission automatically uploads a full PDF + JSON (photos included, every tower included) into the shared company folder — as soon as you have signal. Each upload is under the signing-in tech's own name for accountability, but everyone's reports land in the same place. Visits submitted offline are queued and uploaded the moment connectivity returns. This is the permanent record for the whole team, for years to come.

Emailing and OneDrive sync use the same sign-in — one login covers both.

Price book

The Price Book tab is the single source of truth for every part code, default quantity and price in the picker. Edit a price there and it's live everywhere immediately. Import a .json export from another device, or a plain .csv straight from a spreadsheet price list (columns: category, code, description, qty, price). Export after changes and share the file with other technicians — each device imports it independently.
